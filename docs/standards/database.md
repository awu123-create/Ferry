# 数据库与迁移规范（Database Schema Standard）

新增或修改数据库表、列、索引、约束、触发器或迁移脚本时阅读本文件。通用分级与调用方原则见 [CODING_STANDARDS.md](../../CODING_STANDARDS.md)；DML 读写与并发协调见 [docs/standards/go/code.md](./go/code.md)；真库与迁移往返测试见 [docs/standards/go/testing.md](./go/testing.md)。

表只存储代码真实读取的**业务事实**，Schema 用数据库约束守住不变量。

## 表、列、索引与触发器

- **DDL 归迁移工具，DML 归数据访问层**：一切建表、改列、唯一约束、`CHECK` 约束、部分索引与数据库触发器一律写入版本化 SQL 迁移脚本，**严禁启用 ORM 自动建表/改表（如 `AutoMigrate`）**。
- **调用方原则（Callers）**：任何表、列、索引或枚举值必须在本 PR 中有生产代码读或写，禁止为后续阶段提前预埋未使用的字段或索引（见 [CODING_STANDARDS.md](../../CODING_STANDARDS.md)）。
- **数据库约束兜底**：
  - 表间引用显式声明 `REFERENCES` 外键，并按聚合生命周期决定是否级联删除（从属流水/发件箱随主记录 `ON DELETE CASCADE`，跨聚合历史记录不级联误删）；
  - 封闭状态枚举与数值上下限在数据库层加 `CHECK` 约束。
- **主键、时间与原始字节类型**：
  - 高并发写入的核心实体表主键优先采用按时间递增的 `UUIDv7`，避免随机 `UUIDv4` 造成 B-Tree 索引页分裂；只追加的内部流水或队列表可采用 `BIGSERIAL`；
  - 所有时间戳列统一使用 `TIMESTAMPTZ`，默认值写 `now()`；
  - 需参与幂等摘要比对或密码学签名的原始报文列必须用 `BYTEA` 原样存储，**禁止用 `JSONB`**（防止键序与空白重排破坏字节一致性）。
- **避免热路径瞬态列更新与部分索引对齐**：不在高频执行热路径上反复写入短暂中间状态制造 MVCC 死元组；部分索引（Partial Index）的 `WHERE` 谓词必须与生产查询条件严格一致，确保查询稳定命中索引。

**Judgement.**

- 配置定义、实体生命周期与多次执行审计流水按职责分表存储，不把可追加的历史明细覆盖回主表。
- 能由其他列推导出的状态不单独加冗余列，减少状态不一致风险。
- 每次读取都会回退为固定默认值的列，直接声明 `NOT NULL DEFAULT <值>`，避免应用层反复处理可空指针；仅当“缺失本身具有独立业务语义”时才允许 `NULL`（如尚未完结记录的完成时间）。

## 版本化迁移规范（Migrations）

- 迁移脚本按递增序号存放于 `migrations/NNNN_<slug>.sql`，通过内嵌文件系统与应用迁移入口统一执行。
- 每个脚本必须同时提供 `-- +goose Up` 与 `-- +goose Down`；存储过程与触发器块使用 `-- +goose StatementBegin` / `-- +goose StatementEnd` 包裹；`Down` 必须完整撤销 `Up` 变更（涉及数据搬迁或列拆分时，`Down` 须还原为上一版二进制可读回的形态）。
- **版本号严格高于主干**：分支新增的迁移编号必须严格高于 `main` 上最新版本号。拉齐 `main` 后若发生撞号，**保留 `main` 已有编号不动**，用 `git mv` 将本分支新增的全部迁移按原相对顺序整体顺延，同步更新测试中引用的版本号并重跑集成测试。

**Judgement.** 同一尚未合入 `main` 的 PR 内，若发现本 PR 新增迁移有遗漏或错误，直接原地修改该脚本，不额外追加补丁迁移文件。

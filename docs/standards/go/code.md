# Go 代码规范（Go Code Standard）

编写或评审非测试 Go 业务与基础设施代码时阅读本文件。通用规则与分级定义见 [CODING_STANDARDS.md](../../../CODING_STANDARDS.md)；静态检查配置与仓库自动化测试已强制执行的机械规则（跨包依赖白名单、标准库常量、禁用函数、静态日志短语单测等）以工具与测试输出为准，本文只规定跨项目通用的架构与工程判断条款。

## 模块分层与持久化模型隔离

- **充血领域核**：领域包保持纯 Go 实现，承载聚合不变量、状态流转与值对象校验，不引入 ORM 标签、传输协议标签、HTTP 或数据库驱动依赖。
- **消费方窄接口**：应用编排模块直接消费领域模型，并在各自包内声明最小出站接口（只保留本包真实调用的方法），不设浅层透传中间层。
- **适配器互不耦合**：出站基础设施适配器只依赖领域包与基础工具包隐式实现消费方接口，兄弟适配器之间互不引用；唯一组装根位于 `cmd/*`，显式完成构造与编译期接口断言（`var _ Port = (*Adapter)(nil)`）。
- **DO / PO 严格隔离**：带 ORM 标签的持久化结构体设为包内非导出，每张表集中维护一套双向转换函数，在读写边界统一完成 `.UTC()` 时间规范化与封闭枚举解析。

**Judgement.** 单文件同时承载多块无关能力、同一能力散落多个文件、或单文件逼近 1000 行时，按领域职责重新切分。

**Smell baseline override.** 仓储适配器内完成单次 ORM 查询并执行持久化对象与领域模型互转的方法属于既定适配边界，不判为 **Middle Man**。

## 构造与依赖组装（Construction）

构造函数返回的组件实例必须是**装配完整的**：

- 必需依赖传入 `nil` 时在构造函数直接返回错误；构造成功后的运行路径直接信任依赖非空，不再重复判空或编写二次防空分支。
- 依赖能力一律通过消费方接口显式声明，禁止在运行期对接口做类型断言探测可选方法，避免测试替身漏实现方法却静默跳过关键逻辑。
- 测试切口不污染生产签名，不为测试把必需依赖放宽为可空参数或增加测试开关；确需向黑盒测试暴露内部入口时，通过同包 `export_test.go` 导出。

**Judgement.** 可选运行参数收敛进配置结构体，在构造时一次校验并填充默认值，少用构造后改状态的链式 `With*` 方法。

## 边界解析与原始字节保真（Parsing at boundaries）

承接 [CODING_STANDARDS.md](../../../CODING_STANDARDS.md) 的边界解析规则：

- 需参与幂等摘要比对或密码学签名的入站报文，在边界校验语法合法性后全程按原始 `[]byte` 传递与落盘，禁止反序列化后再重新序列化破坏字节一致性。
- 封闭值域状态与错误分类定义独立命名类型及 `Parse*` 函数；从外部存储或请求读回字符串时统一走解析函数校验，拒绝未知值，禁止直接类型强转。

**Smell baseline override.** 本节规则裁决 **Primitive Obsession**；标准 UUID 与常规毫秒数值配置不在其列。

## 持久化切口与并发协调（Persistence seams and concurrency）

- **业务原子切口**：持久化层向上暴露完整的业务原子方法（在仓储内部封装同事务发件箱写入与行锁生命周期），不向应用层暴露裸事务句柄（`BeginTx` / `UnitOfWork`）。
- **提交前并发守卫**：并发前置条件必须在提交时刻依然成立，禁止“事务外先普通查询判断、随后无锁更新”：
  - 幂等创建依赖数据库唯一约束与冲突不覆盖子句（如 `ON CONFLICT DO NOTHING`），冲突未插入时在同事务回查并校验快照一致性；
  - 队列抢占与批量重放使用 `FOR UPDATE SKIP LOCKED`，包含外部回调的锁事务必须绑定短硬超时，防止下游抖动拖成长事务阻塞数据库清理；
  - 状态机推进与配置并发修改使用条件更新（携带乐观版本、状态集合或预期更新时间）并校验 `RowsAffected`。
- **原子脚本与服务端时钟**：跨 Key 读写或“先核对持有人 token 再续期/删除”的缓存操作统一封装为原子脚本，并在脚本内读取服务端当前时间（如 Redis `TIME`）消除跨机时钟偏差；禁止对分布式互斥锁执行无条件裸 `DEL`。
- **锁/租约保护的多步共享超时**：持有带过期时间的租约或互斥锁执行多步 I/O（包含进程停机时的 `context.WithoutCancel` 收尾步骤）时，整条持锁链路必须共享同一个**严格小于锁/租约有效期**的总截止时间，禁止按单步分别设置独立超时导致累计耗时超过锁/租约有效期。
- **连续水位消费的收尾错误边界**：在按分区连续完成水位提交且无单条重排能力的消费模型中，一旦业务副作用已成功持久化，后续自带 TTL 过期兜底的收尾清理（如释放短锁）若遇瞬时网络报错，只记录 `Warn` 日志并放行消费确认，不得返回错误冻结整条分区的提交水位。
- **无驱逐内存实例的有界 TTL**：在禁止淘汰（`noeviction`）的内存实例上新增任何协调或防重 Key 族时，必须采用与外部输入截止时间解耦的有界常量过期时间，防止远期参数将临时 Key 变成长期驻留内存的死键。

## 错误处理（Errors）

错误单向向上传递并只处理一次（见 [CODING_STANDARDS.md](../../../CODING_STANDARDS.md)）：

1. 领域层定义业务 sentinel（`ErrXxx`）与结构化校验错误类型；
2. 基础设施层将驱动层语义错误翻译为领域 sentinel，其余系统错误按 `<小写动词> <业务对象>: %w` 包装返回；
3. 入站边界层（HTTP Handler、后台循环顶层）集中通过 `errors.Is` / `errors.As` 分流响应码或退避动作，未识别系统错误只记录一次 `Error` 日志并对外返回脱敏通用错误。

- 错误分支只匹配 sentinel 或错误类型，禁止匹配 `err.Error()` 文本。
- 运行期异常与外部输入错误一律返回 `error`，禁止用 `panic` 处理运行期异常；`os.Exit` 只允许出现在 `cmd/*/main.go`。

**Judgement.** 上层需要通过 `errors.Is` / `errors.As` 识别根因时用 `%w`；在有意阻断底层驱动类型向上泄漏的边界用 `%v`。

## 出站调用（Outbound calls）

- 禁止在数据库事务内发起不可控外部 HTTP 请求或远程调用（绑定短硬超时的发件箱批量派发除外）。
- 出站 HTTP 客户端必须绑定带超时的 `ctx`、按安全边界显式控制 3xx 重定向、使用 `io.LimitReader` 限制响应体读取上限并确保关闭 `resp.Body`；底层客户端只执行单次尝试，不内置隐式重试。

## 日志与指标（Logging and metrics）

- 日志只在系统边界层（入站接口、后台调度/消费循环、数据库慢查询适配器、进程启停入口）输出；纯领域层零日志依赖。
- 需要打日志的组件通过构造函数显式注入结构化 Logger，不使用包级全局 Logger；动态上下文统一放入 `snake_case` 结构化字段，错误对象通过结构化错误字段携带，不在日志消息中拼接动态参数。
- 严禁将签名密钥、数据库凭据、缓存密码、`Authorization` 头或未脱敏敏感报文写入日志或对外错误响应。
- 监控指标标签只允许取封闭低基数集合（状态类别、错误分类、HTTP 状态段等），禁止将请求 ID、任务 ID 或原始目标 URL 设为标签。

**Judgement.** 日志级别约定：

| 级别 | 含义 |
| :--- | :--- |
| `Error` | 需要人工介入排查的异常。 |
| `Warn` | 进程已自愈或按预期降级处理（如退避重试、探针失败、带 TTL 锁释放超时）。 |
| `Info` | 进程启停生命周期与关键阶段节点完成。 |
| `Debug` | 本地排障细节，生产默认关闭。 |

## 时间、Context 与 Goroutine

- 所有持久化与领域计算时间统一规范化为 `.UTC()`。
- 涉及业务判定与落库的时间必须可注入：纯领域与仓储方法由调用方显式传入 `now time.Time`，编排层通过可注入时钟函数（默认 `time.Now`）获取当前时间；仅纯耗时统计（如 `time.Since`）可直接调用 `time.Now()`。
- `context.Context` 作为所有 I/O 函数的第一个参数。
- 每个启动的 goroutine 必须有明确归属方负责通知停止并等待退出（`sync.WaitGroup` 或 `errgroup`）；优雅停机须将“停止接收新工作的 `ctx`”与“排空在途工作的 `drainCtx`”分离，保证收到停机信号后在途工作能完整落盘收尾。
- `init()` 禁止执行任何 I/O 或初始化全局可变运行时状态，启动装配统一在 `cmd/*/main.go` 显式完成。

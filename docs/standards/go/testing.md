# Go 测试规范（Go Testing Standard）

编写或评审 Go 测试、或决定一条行为归哪一层测时阅读本文件。通用分级见 [CODING_STANDARDS.md](../../../CODING_STANDARDS.md)；`testpackage`、`thelper`、`noctx`、`bodyclose` 等已由静态检查强制执行的机械规则以工具输出为准。

## 测试归属与真实依赖边界（Owners）

一个行为只在拥有它的那一层测一次；其他层级已覆盖的分支不在上层重复复制。

- **并发锁与存储原语必测真实例**：数据库唯一约束冲突、`FOR UPDATE SKIP LOCKED`、乐观版本 CAS、触发器通知以及缓存原子脚本（Lua 互斥锁、租约与状态门禁）必须在真实数据库与缓存实例中验证；内存 fake 无法证明并发锁与事务隔离语义。
- **消除冗余映射与细碎端到端分支**：若真实存储测试已覆盖完整的表读写与模型转换，不额外保留纯内存的结构体互转测试；端到端集成测试只验证跨组件主链路与故障交错，不重复枚举单测已覆盖的参数校验分支。

**Judgement.** 保留任何测试前反问一句：删掉它之后，有没有真实缺陷会漏过去？没有就删。

## 运行约定与 `-short` 分流

需要真实数据库、缓存或消息队列的测试，在连接准备入口统一使用 `testing.Short()` 分流：

```go
if testing.Short() {
	t.Skip("skipping real middleware test in -short mode")
}
```

- 带 `-short` 运行单测套件时自动跳过外部容器测试，保持秒级反馈；
- 不带 `-short` 运行集成测试套件时，只要连接不上目标中间件必须直接 `t.Fatalf` 失败退出，严禁静默 `t.Skip` 混成通过；
- **禁止**添加 `//go:build integration` 构建标签，确保日常编译与静态检查始终覆盖全部集成测试源码，防止重构签名后集成测试静默腐烂；
- 集成测试统一带 `-count=1` 禁用结果缓存；用 `-run` 单独运行指定用例时，必须核对输出不含 `[no tests to run]`（正则未命中任何测试时 `go test` 仍返回退出码 0）。

## 包名、文件与表驱动命名

- **黑盒包名优先**：验证包对外行为的测试使用 `package <pkg>_test`；仅在独立验证复杂非导出核心算法时显式豁免白盒包名，或通过同包 `export_test.go` 暴露最小测试切口。
- **文件与函数命名**：单元测试命名为 `<subject>_test.go`（同包多文件共用的内存替身拆为 `fake_<port>_test.go`），函数按 `Test<Subject>_<Behavior>` 命名；端到端集成测试命名为 `<scene>_integration_test.go`，函数按 `Test<Scene>Integration` 命名。
- **表驱动子用例名**：多组同类边界输入使用表驱动配合 `t.Run` 组织，子用例名称只使用字母、数字、下划线或连字符，**禁止包含 `/`**（防止 `go test -run` 按路径分隔符误切）。

## Fake 纪律、异步等待与边界断言

- **单接口单内存 Fake**：同一个包内，每个消费方接口只维护一份内存 fake，新测试需要并发钩子或注入故障时在原 fake 上扩展，不另起平行类型，也不跨包抽大一统 mock。
- **禁嵌入接口凑编译**：禁止测试替身通过嵌入接口（embedded interface）省掉未用方法（漏实现的方法会在运行期触发 nil panic）；单场景 stub 未配置的方法必须显式失败（`t.Fatalf` 或返回错误），完整内存 fake 按真实业务语义返回领域错误。
- **按需记录状态**：Fake 上的计数器或调用切片只在确实有测试断言读取它时才添加。
- **禁 `time.Sleep` 盲等异步结果**：异步并发交错使用通道栅栏、就绪信号或带超时的条件轮询 `waitUntil` 精确同步，不靠固定睡眠猜测执行进度。
- **容差窗口内测早到边界**：当被测时间守卫带有时钟偏差容差（例如 `1s` 容差）时，验证“不得提前触发”的测试输入必须落在容差窗口以内（例如提前 `500ms`），防止用远大于容差的时间差绕过早到漏洞。
- **消息流负向断言带对照探针**：验证消息队列或异步流“未发出/未投递某条消息”时，禁止仅靠轮询超时未读到消息就判通过；必须在同一消费组内投递一条更晚到期的对照消息并确认收到该对照消息，证明消费者已完成分区分配且扫描已越过目标时间点。
- **逆序清理资源**：集成测试在 `t.Cleanup` 中按启动逆序收尾——先停后台消费与调度协程，再关模拟下游服务、消息队列与缓存连接，最后销毁隔离的临时数据库，防止先断底层连接造成后台协程刷屏或竞态。

## 数据迁移往返测试

普通建表与索引迁移随真实存储测试自动验证；涉及**转换、拆分或回填存量数据**的迁移脚本，必须补写往返测试：先将临时库迁移至 `N-1` 版本写入旧格式数据 → 升级至 `N` 版本断言转换结果 → 执行 `Down` 回滚验证旧版逻辑仍可无损读取。
